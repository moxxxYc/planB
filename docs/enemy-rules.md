# 敌人波次与反制规则

**最后更新：** 2026-06-04
**仓库状态：** 纯文档态，无当前正式实现。
**权威范围：** 敌人波次、机器反制预警、反制生效规则。

本文只定义 MVP 基础敌人压力。战场结算见 `docs/battlefield-rules.md`，机器组件见 `docs/machine-warehouses.md`。

## 1. 目标

敌人要做两件事：

1. 用单位波次在三路战场上制造真实压力。
2. 用可预警的反制攻击机器组件，迫使玩家强化、转向或补洞。

敌人不是单纯加血加攻。反制也不是沉默删除构筑。

## 2. 硬边界

当前不做：

- 完整敌人表。
- 完整 Boss 阵容。
- 复杂敌人 AI。
- 自由 RTS 寻路。
- 没有预警的删球、锁槽、禁用队列。
- 同时把三类反制堆到同一场普通战斗。
- 用纯数值压死玩家。

## 3. 敌人波次模型

MVP 第一版使用波次脚本，不需要节点地图或完整遭遇池。

每场战斗声明：

| 字段 | 含义 |
|---|---|
| `battle_id` | 战斗编号。 |
| `duration_target` | 目标战斗时长。 |
| `lane_pressure_plan` | 三路施压顺序。 |
| `enemy_entries` | 敌人何时、在哪路、以多少数量生成。 |
| `counter_family` | 本场是否启用机器反制。 |
| `endpoint_behavior` | 是否启用终点 Guardian 行为。 |

波次不直接改变机器。机器反制必须走独立的反制规则。

## 4. 最小敌方单位模板

这是调试用最小模板，不是完整敌人表。

| 模板 | HP | 攻击 | 间隔 | 速度 | 用途 |
|---|---:|---:|---:|---:|---|
| `Enemy Grunt` | 10 | 2 | 1.0s | 7 | 基础同路接战。 |
| `Enemy Raider` | 7 | 1 | 0.7s | 10 | 漏兵压力和路线危险提示。 |
| `Enemy Brute` | 24 | 4 | 1.4s | 5 | 破门压力，不能高频出现。 |

限制：

- 第一版普通战斗最多同时使用 2 个模板。
- 终点战最多使用 3 个模板。
- 不做远程、召唤、治疗、跨路攻击，除非后续命名敌人明确加入。

## 5. 普通战斗波次节奏

普通战斗目标 90-150s。

第一版节奏：

| 时间 | 压力 |
|---:|---|
| 0-8s | 读场时间，只允许轻微敌人出生。 |
| 8-35s | 单路或双路基础波次。 |
| 35-70s | 引入路线偏压，让 `Deploy Lane` 有选择价值。 |
| 70-110s | 当前机器构筑应开始转成明显战场优势。 |
| 110s 后 | 若仍未结束，逐步加敌人波次，不加隐藏数值。 |

路线压力原则：

- 一场普通战斗至少有一次明确主压路线。
- 主压路线必须提前 3s 以上显示危险提示。
- 不要三路同时满压。那会让 `Deploy Lane` 退化成救火按钮。
- 如果玩家看不出哪一路危险，先强化敌人出生预告，不先加 UI 文案。

## 6. 反制总合同

每个反制必须声明：

- 攻击哪个机器组件。
- 预警在哪里出现。
- 预警持续多久。
- 生效期间改了什么。
- 玩家有哪些机器层面的解法。
- 它如何避免硬删除构筑。

统一参数：

| 参数 | 起点 |
|---|---:|
| 首次反制出现时间 | 战斗开始后 25-40s |
| 预警时长 | 3-5s |
| 反制活跃时长 | 12-20s |
| 同场反制家族数量 | 普通战斗最多 1 |
| 同场反制触发次数 | 普通战斗 1-2 次 |

反制必须在机器 UI 和战场压力之间形成因果关系。玩家应该能说出“它攻击了我的 Pool / Echo / 队列空档”，而不是只感觉敌人变强。

## 7. Pool Polluter

攻击对象：`Launch.Pool`、回流节奏、Junk 处理。

第一版规则：

| 项 | 起点 |
|---|---|
| 预警 | Pool 旁出现 Junk 预备格，持续 4s。 |
| 生效 | 向 Pool 插入 1 个 Junk Ball。 |
| 活跃期 | 18s。 |
| 活跃期追加 | 每 6s 尝试再插入 1 个 Junk Ball，最多 2 次。 |
| 上限 | 第一版同一时间 Pool 内最多 2 个 Junk Ball 来自本反制。 |

玩家读法：

- Pool 可见容量被占。
- Launcher 发出 Junk 后没有有效 Unit 结算。
- 回流被挤掉时要有明确丢失反馈。

预期解法：

- 扩 Pool。
- 过滤 Junk。
- 净化 Junk。
- 把 Junk 转成低价值 clean ball。
- 增强 Split / Recycle 的前插或缓冲。

禁止：

- 直接删除 clean ball。
- 在无预警情况下塞满 Pool。
- 把 Junk 做成所有 Boss 默认机制。

## 8. Echo Breaker

攻击对象：`Tuning.Echo` 窗口或 Echo 命中结果。

第一版规则：

| 项 | 起点 |
|---|---|
| 预警 | Echo 槽出现裂纹标记，持续 4s。 |
| 生效 | 活跃期内下一次 Echo 复制被降级为普通 Gate 结算。 |
| 活跃期 | 14s。 |
| 触发次数 | 每次活跃期最多吞 1 次 Echo 复制。 |
| 冷却 | 同场第二次 Echo Breaker 至少间隔 25s。 |

玩家读法：

- Echo 槽被明确标记。
- Echo 被吞时显示“复制失败”或等价反馈。
- Unit 进度少了一次复制，而不是球消失。

预期解法：

- 转向 Prime 或 Surge。
- 保护 Echo 窗口。
- 用诱饵触发一次失败。
- 增加 Echo 触发频率，用数量穿过干扰。

禁止：

- 整场禁用 Echo。
- 禁用所有 Tuning 奖励槽。
- 让玩家误以为物理球被吞。

## 9. Stagger Punisher

攻击对象：`Unit.Queue` 断档、蓄力空窗、长时间无部署。

第一版规则：

| 项 | 起点 |
|---|---|
| 监测 | 玩家连续 4s 没有部署队列条目。 |
| 预警 | 最危险路线出现突袭预告，持续 3s。 |
| 生效 | 在该路线生成 2 个 `Enemy Raider`。 |
| 活跃期 | 16s。 |
| 触发次数 | 每次活跃期最多 2 次。 |

玩家读法：

- 队列空档计时器出现。
- 路线危险提示和 Raider 出生位置一致。
- 它惩罚“长时间等大批”，不惩罚所有 Unit 构筑。

预期解法：

- 用低阶单位填补空档。
- 拆批部署。
- 提前切到危险路线。
- 使用队列保护或临时守线修正。

禁止：

- 直接清空队列。
- 直接禁止批量冲锋。
- 每次蓄力都固定惩罚，导致 Unit 轴不可玩。

## 10. MVP 遭遇顺序

一局不需要看到所有反制。MVP 需要三类反制都能被验证，但单局可以根据玩家主轴只出现 1-2 类。

第一版短局结构：

| 战斗 | 目的 | 反制 |
|---|---|---|
| Battle 1 | 新手引导，展示三仓因果。 | 无。 |
| Battle 2 | 让玩家看到当前机器方向开始成形。 | 无或极轻路线压力。 |
| Battle 3 | 第一次反制，攻击当前最强机器轴。 | `Pool Polluter` / `Echo Breaker` / `Stagger Punisher` 三选一。 |
| Battle 4 | 商店后验证补洞或继续强化。 | 轻量路线压力。 |
| Battle 5 | 第二次反制，强度略高。 | 优先复测同家族，也可换相邻弱点。 |
| Endpoint | 检查机器优势能否转成基地圈输出。 | Endpoint Guardian + 1 个反制家族。 |

如果后续需要 8 场短局，新增战斗只用于更平滑地介绍反制，不用于塞更多敌人类型。

## 11. 失败模式

- 玩家只感觉敌人变硬，不知道机器哪里被攻击。
- 反制没有预警，像惩罚。
- 反制直接删除构筑，玩家只能重开。
- Stagger Punisher 让 Unit 轴不能蓄力。
- Pool Polluter 把所有战斗都变成清垃圾。
- Echo Breaker 让 Tuning 读起来像随机失效。
- 三路同时满压，`Deploy Lane` 变成泛用救火。
