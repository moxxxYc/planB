# 基础战场规则

**最后更新：** 2026-06-10
**仓库状态：** 文档主导，MVP v0 实现已在 `mvp/` 启动；本文不作为代码状态证明。
**权威范围：** 三路战场、单位接战、门、基地圈、Guardian 战斗、胜负结算。

本文不定义机器细节。机器入口见 `docs/machine-warehouses.md`。

## 1. 战场目标

战场必须展示真实的自动单位战斗，而不是三条抽象进度条。

玩家应该能从单位位置和战斗状态看出：

- 哪一路正在推进。
- 哪一路正在僵持。
- 哪一路正在漏兵。
- 哪个机器方向正在转化成前线优势。

## 2. 战场拓扑

基础战场是：

- 左侧玩家基地圈。
- 右侧敌方基地圈。
- 三条固定路径：`Left / Mid / Right`。
- 每边每路一个 `Lane Gate / portal`，位于基地圈和路径的连接处。
- 玩家侧 Guardian 位于玩家基地圈内侧；三条路线的玩家侧出兵口 / Lane Gate 位于基地圈的路线连接边缘。
- Guardian 与三条玩家侧出兵口之间必须保留基地缓冲区，用于读出破门后入侵、Guardian 攻击和 Guardian 受压。

路径可以在视觉上弯曲，但规则上按一维有序路径处理。

第一版规则坐标：

- 每条路线使用 `0-100` 的标准化路径坐标。
- 玩家基地圈接触区：`0-8`。
- 玩家侧 Lane Gate：`8`。
- 敌方侧 Lane Gate：`92`。
- 敌方基地圈接触区：`92-100`。
- 玩家单位向 `100` 前进。
- 敌方单位向 `0` 前进。

实现可以使用路线样条、路径点链或任意等价的有序路径坐标。不需要自由地图寻路。

## 2.1 基地缓冲区与出兵口

玩家侧基地圈内部必须区分三个位置概念：

```text
玩家基地圈内部
┌────────────────┐
│  Player        │
│  Guardian      │
│        ○ ○ ○   │  Left / Mid / Right 出兵口与 Lane Gate
└────────┼─┼─┼───┘
         L M R
```

规则：

- `Player Guardian` 是基地圈内的固定战场实体，不是出兵点。
- 三条路线各有一个玩家侧出兵口，位于基地圈连接战场路径的一侧。
- 玩家单位从当前 `Deploy Lane` 对应的出兵口出生。
- 出兵口和 Lane Gate 可以在视觉上合并为同一位置或紧邻结构，但必须读成路线入口 / 防线，不读成 Guardian 身体的一部分。
- Guardian 与出兵口之间的基地缓冲区用于表现敌人破门后进入基地圈、Guardian 开始防守、Guardian 受到压力。
- Guardian 基础攻击和战术技能可以覆盖基地缓冲区，但不应覆盖整条路线。

失败信号：

- 玩家以为单位从 Guardian 身上出生。
- 敌人碰到出兵口的瞬间就像已经贴脸打 Guardian。
- `破门`、`入侵` 和 `Guardian 受压` 三种状态无法区分。

## 3. Deploy Lane 在战场中的作用

`Deploy Lane` 决定后续队列条目部署到哪一路。

规则：

- 玩家选择当前 `Deploy Lane`。
- 队列条目在部署节拍时读取当前路线。
- 批量部署开始时锁定路线。
- 已部署单位不受后续路线切换影响。
- 路线选择不改变机器产出，不改变单位类型，不直接控制单位。

## 4. 单位模板字段

基础单位可以有：

| 字段 | 含义 |
|---|---|
| `hp` | 生命值。 |
| `attack_damage` | 基础攻击伤害。 |
| `attack_interval` | 攻击间隔。 |
| `attack_range` | 攻击距离。 |
| `move_speed` | 无目标时沿路径移动速度。 |
| `body_size` | 可视体积和站位间隔。 |
| `target_rule` | 索敌规则，基础为同路最近敌人。 |
| `skill_rule` | 可选简单技能钩子，默认空。 |

## 5. 单位战斗规则

基础战斗是同路接战：

- 单位始终属于一条路线。
- 单位沿所属路径向敌方前进。
- 当同路敌人进入攻击范围，单位停下或减速并按攻击间隔攻击。
- 基础索敌是同路最近敌人。
- 单位不攻击其他路线，除非命名技能或后续规则明确允许。
- HP 降到 0 时死亡。
- 接战清空后，存活单位继续前进。
- 技能可以存在，但 MVP 基础技能应为简单触发，不做完整战术 AI。

不做复杂碰撞推挤。前线推进来自接战胜负，不来自物理挤压。

## 6. 战场结算合同 1.0

每条路线独立结算。

基础结算顺序：

1. 队列部署到当前 `Deploy Lane`。
2. 敌方波次在各自路线生成。
3. 单位沿路径移动。
4. 同路单位进入攻击范围后接战。
5. 一方接战单位死亡后，存活方继续推进。
6. 到达敌方 Lane Gate 后攻击 Gate。
7. Lane Gate HP 归零后，该路线进入敌方基地圈。
8. 进入基地圈的单位攻击对应 Guardian。
9. 敌方单位同理可以破玩家侧 Gate。
10. 敌方单位从对应路线进入玩家基地缓冲区。
11. 进入玩家基地缓冲区的敌方单位攻击 `Player Guardian`，`Player Guardian` 也可以按基地圈内空间关系反击。
12. 任一 Guardian HP 归零后战斗结束。

目标优先级：

| 单位所处状态 | 基础目标 |
|---|---|
| 路线上有同路敌方单位 | 最近敌方单位。 |
| 无敌方单位且敌方 Gate 未破 | 敌方 Lane Gate。 |
| 敌方 Gate 已破且进入基地圈 | 敌方 Guardian。 |
| Guardian 基地圈内有敌方单位 | 最近入侵单位。 |

Gate 被打破后，本场战斗内保持打破状态，不自动修复。

## 7. 路线状态

每条路线应能从战场读成以下状态：

| 状态 | 玩家读法 |
|---|---|
| 推进 | 我方单位接战后仍存活，并向敌方侧移动。 |
| 僵持 | 双方单位在路径上持续接战，前线位置短时间不明显移动。 |
| 漏兵 | 敌方单位突破我方接战并靠近玩家侧门或基地圈。 |
| 破门 | Lane Gate HP 归零，后续单位可进入基地圈。 |
| 入侵 | 单位已经进入敌方基地圈，正在攻击 Guardian。 |

不应依赖隐藏压力值解释路线结果。

## 8. Lane Gate

基础每路终端都有固定 HP 的 `Lane Gate`。

规则：

- 敌方侧 Lane Gate 保护敌方基地圈。
- 玩家侧 Lane Gate 保护 `Player Guardian`。
- Lane Gate 固定不动，有 HP，可被同路单位攻击。
- Lane Gate 不攻击、不施法、不移动。
- Lane Gate 不是建筑系统，不是塔防层，不是 Dota 式塔网。
- Lane Gate 的作用是减缓滚雪球，让推进和漏兵状态更可读。
- Lane Gate 被破后，该路不再拦截单位。

失败信号：

- 玩家大部分时间只看单位打门，说明 Lane Gate HP 或波次节奏过厚。

## 9. 玩家侧 Guardian

`Player Guardian` 是玩家基地在战场上的可见对象。

战场规则：

- 固定在玩家基地圈。
- 与三条玩家侧出兵口保持可见距离，中间留有基地缓冲区。
- 有 HP、基础攻击、攻击间隔、攻击范围。
- 可以攻击进入玩家基地接触区 / 基地缓冲区的敌方单位。
- 基础攻击是防偷家的普通手段，独立于 Guardian 战术技能。
- 不移动、不寻路、不离开基地圈。
- 不攻击敌方 Guardian。
- 不接受玩家直接操作。
- 受到的伤害就是玩家基地伤害。
- 敌方单位进入玩家基地圈后，Guardian 基础攻击和战术技能按基地圈内空间关系选目标，不再按路线筛选。
- Guardian 的攻击范围不应覆盖整条路线，否则它会替代 Lane Gate、Deploy Lane 和单位稳线。
- 单位可以保留 `entered_from = Left / Mid / Right` 作为危险来源、日志或结果页字段，但 `entered_from` 不能作为 Guardian 战斗筛选规则。

基础攻击可以清理少量入侵单位，避免单个漏兵直接偷家；如果 `Player Guardian` 能独自清掉持续漏兵，让玩家不用靠球机和 `Deploy Lane` 稳线，它就太强。

Guardian 的构筑层规则见 `docs/guardian-system.md`。

## 10. 敌方终点 Guardian

敌方基地可以表现为 `Base Guardian / Endpoint Guardian`。

规则：

- 固定在敌方基地圈。
- 作为当前战斗目标或终点战目标。
- 不需要完整 Boss 阵容。
- 在敌方 Lane Gate 被破后，后续我方存活单位进入对应基地接触区攻击它。
- 它可以攻击基地接触区内的单位。

MVP 当前接受的终点战行为：

`Telegraphed Sweep`

- 常规攻击照常进行。
- 每 9s 选择被突破且入侵单位最多的基地接触区。
- 若并列，优先最近对 Guardian 造成伤害的接触区。
- 先显示 1.2s 蓄力预警标记。
- 结算时造成范围伤害。
- 对命中单位施加短距离沿路击退。
- 击退只沿当前路径或接触区轴线后退，不跨路、不眩晕、不减速、不重置目标。

失败信号：

- 扫击不可预判，说明反馈不足。
- 扫击经常清空完整胜利波，说明惩罚过重。
- 击退导致跨路、卡住或复杂修路，说明实现超出 MVP 战场模型。

## 11. 胜负条件

第一版基础方向：

- 玩家胜利：敌方 Endpoint Guardian HP 降到 0。
- 玩家失败：`Player Guardian` HP 降到 0。

普通战斗和终点战使用同一套胜负结算。区别只在敌人波次、Endpoint Guardian HP、终点行为是否启用。

## 12. 第一版可调数值目标

这些数值是调试起点，不是最终平衡承诺。

参考单位：

| 参数 | 起点 |
|---|---:|
| `hp` | 10 |
| `attack_damage` | 2 |
| `attack_interval` | 1.0s |
| `attack_range` | 3 路径单位 |
| `move_speed` | 8 路径单位/s |

战场对象：

| 对象 | 起点 | 目标读法 |
|---|---:|---|
| Lane Gate HP | 60 | 无人防守时，3-5 个参考单位能较快破门；单个单位不能让玩家误以为已经赢线。 |
| Player Guardian HP | 100 | 能承受少量漏兵，但连续漏兵会很快失败。 |
| 普通战斗 Endpoint Guardian HP | 120 | 普通战斗能在短时间内结束，不拖成长 Boss。 |
| 终点战 Endpoint Guardian HP | 180 | 需要至少一次明确破门和基地圈持续输出。 |
| Guardian 基础攻击 | 5 / 1.5s | 能清理少量入侵，但不能替玩家稳住整局。 |
| Telegraphed Sweep 伤害 | 8 | 打残参考单位，不应稳定秒杀满血波次。 |
| Telegraphed Sweep 击退 | 8 路径单位 / 0.35s | 打断基地圈输出，但不把单位推出本路线规则模型。 |

节奏目标：

| 项 | 目标 |
|---|---|
| 同等参考单位 1v1 击杀时间 | 4-6s |
| 出生到首次接战 | 8-14s |
| 正常战斗长度 | 90-150s |
| 终点战长度 | 150-210s |
| 破门后到胜利的可见窗口 | 15-35s |
| 连续漏兵到失败的窗口 | 20-40s |

如果调试时所有战斗都超过目标，优先减 Gate HP 或波次间隔，不先加单位伤害。

如果调试时玩家只看 `Deploy Lane`，优先降低选路本身的收益或提高机器输出差异，不先加更多路线 UI。

## 13. 战场失败模式

- 三路读起来只是三条进度条。
- `Deploy Lane` 比球机构筑更重要。
- 所有机器轴最终都只读成“更多单位”。
- 玩家看不出是机器轴、路线选择还是敌人反制导致了胜负。
- 战场需要标签解释才能理解推进、僵持和漏兵。
- Guardian 独自清漏兵，导致球机和路线选择都不重要。
- Lane Gate 太厚，导致战场像打桩。
