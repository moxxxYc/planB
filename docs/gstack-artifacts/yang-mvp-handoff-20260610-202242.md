## 1. Build Target

What this build produces in one sentence:

> A minimum playable, player-facing UI flow for PlanB MVP v0: `Main Menu -> Guardian Contract -> Battle Screen -> Battle Result -> Reward / Shop / Rest -> Final Result`, with no Debug UI and with Battle Screen showing machine output flowing through Queue Bridge into the selected lane spawn port.

Hypothesis:

> Players can read the causal chain `machine output -> Queue / Deploy Bridge -> selected spawn port -> three-lane battlefield result`, while also reading Guardian as an in-world attacking base entity rather than a HUD panel, hero unit, or spawn point.

Soul of this build:

1. Queue Bridge must visibly connect queue output to the currently selected spawn port.
2. Guardian must read as an in-world base entity with attached status, not as a HUD panel or spawn source.

If either fails, the UI may still "work", but it is not the intended Battle UI.

## 2. Scope

### In Scope

- [ ] MUST: Main Menu enters the formal run flow through `Guardian Contract`.
- [ ] MUST: Guardian Contract lets player choose `巢脉母` or `酸冠母` before Battle 1.
- [ ] MUST: Battle Screen uses the three-zone layout: `三仓机器 38% | Queue / Deploy Bridge 14% | 战场 48%`.
- [ ] MUST: Battle Screen shows `Launch / Tuning / Unit`, queue head, selected lane, three lanes, player-side spawn ports, player Guardian, enemy Guardian / Endpoint, lane gates, lane danger, and deployment confirmation.
- [ ] MUST: Player Guardian and the three player-side spawn ports are separate objects with visible base buffer space between them.
- [ ] MUST: Units spawn from the selected lane's player-side spawn port, not from Guardian.
- [ ] MUST: `Queue / Deploy Bridge` points to the selected spawn port and updates when `Deploy Lane` changes.
- [ ] MUST: `Deploy Lane` remains direct lane clicking. No standalone three-button lane panel as the primary input.
- [ ] MUST: Battle Result shows win/loss, small three-lane recap, key cause tags, Gold result when relevant, and next action.
- [ ] MUST: Reward Choice shows machine-axis cards with target component, operation, player read, and risk.
- [ ] MUST: Shop / Rest shows Gold, one neutral modifier purchase quota where relevant, item cards, Rest cost/effect, and remaining rest uses.
- [ ] MUST: Final Result summarizes the whole run: Guardian contract, main machine axis, key choices, largest pressure, run path, and next-run observation.
- [ ] MUST: Debug UI, dev sliders, telemetry dumps, implementation-state text, old debug scenes, and test-only controls do not appear in the player-facing flow.

### Should

- [ ] SHOULD: Battle Screen keeps top bar minimal: battle number, Gold only if relevant, selected Guardian identity marker.
- [ ] SHOULD: Bottom event strip appears only if it carries player-facing high-value events: major machine result, lane danger escalation, Guardian tactical trigger, or public enemy counter warning.
- [ ] SHOULD: Battle Result uses a small three-lane recap map rather than only text.
- [ ] SHOULD: Reward / Shop pages preserve `Launch / Tuning / Unit` color and icon language from `docs/DESIGN.md`.
- [ ] SHOULD: Guardian tactical trigger feedback appears around the Guardian or affected invaders, not in a separate log panel.

### Could

- [ ] COULD: Add hover / focus details for Guardian range, card explanation, and lane labels if mouse / keyboard UX needs it.
- [ ] COULD: Add short transition animations between result and reward / shop pages.
- [ ] COULD: Add placeholder audio ticks for deploy, lane danger, and Guardian tactical trigger if quick to wire.

### Out of Scope

- Complex save / continue page, excluded from first UI pass.
- Codex / glossary page, excluded from first UI pass.
- Standalone enemy preview page, excluded from first UI pass.
- Multi-Guardian team editor, excluded because MVP uses one selected Guardian for the run.
- Long-term progression pages, excluded because MVP has no meta progression.
- Guardian equipment, treasure slots, upgrades, skill tree, or direct commands.
- New gameplay rules, new rewards, new enemies, new counter families, new combat balance.
- Final art pass, final sprite sheets, final fonts, final sound mix.
- Steam, account, backend, networking, PVP.
- Any Debug UI unless explicitly requested later.

### Placeholder OK

- Placeholder OK: Guardian sprites can be large readable silhouettes.
- Placeholder OK: Unit and enemy sprites can be simple readable shapes or existing placeholder sprites.
- Placeholder OK: Spawn ports / Lane Gates can be geometric portals, hatches, or markers.
- Placeholder OK: Three-lane battlefield can use simple lightly curved paths.
- Placeholder OK: Machine board internals can use simple pegs, dots, slot boxes, and progress bars, as long as labels and feedback are readable.
- Placeholder OK: Reward / shop cards can use axis icons and text instead of final illustrations.
- Placeholder OK: Result pages can be text-heavy if the three-lane recap and cause tags are clear.
- Placeholder OK: Audio can be absent or simple placeholders. Visual readability cannot depend on audio.

## 3. Gameplay Requirements

| Player Action | Expected Response | Timing | Feel Target |
|---|---|---|---|
| Click `开始新短局` | Enter Guardian Contract page. | Immediate page change or short transition. | The player starts a run, not a tutorial lecture. |
| Select Guardian contract | Selected Guardian card highlights. Preview shows machine bias, battle trigger, suitable tendency, risk. | Highlight updates immediately. | The choice reads as "run contract", not direct hero control. |
| Confirm Guardian | Enter Battle 1 with chosen Guardian identity shown minimally. | Immediate or short transition. | The run starts with a clear anchor. |
| Glance at Battle Screen | Player can identify machine zone, Queue Bridge, selected lane, selected spawn port, player Guardian, enemy Guardian, and highest danger lane. | Within 1 second. | War-table clarity. Dense, but not noisy. |
| Click a battlefield lane | Current `Deploy Lane`, lane highlight, spawn port highlight, and Queue Bridge line update. | Same frame or next frame. | Direct and physical. The lane itself is the control. |
| Queue entry deploys | Queue head confirms, Bridge flashes / connects to selected spawn port, selected spawn port flashes, unit appears from that port. | Bridge and spawn flash visible 0.3-0.5s around deploy. | The player sees "machine output landed there". |
| Enemy approaches player-side gate | Lane danger escalates using enemy-color shape / pulse, separate from selected-lane highlight. | Danger update visible before breach. | Threat, not recommendation. |
| Enemy breaks gate and enters base | Enemy crosses from lane gate into base buffer; Guardian attacks or tactical feedback happens around Guardian / invader. | Breach and base entry are visually distinct moments. | The player reads `破门 -> 入侵 -> Guardian 受压`. |
| Battle ends | Battle Result appears with win/loss, small lane recap, key cause tags, and next step. | No debug dump. | The player understands why the fight ended. |
| Choose reward | Card selection highlights. Preview explains warehouse, component, operation, read, and risk. | Immediate highlight. | The player chooses a machine change, not a generic buff. |
| Buy shop item / Rest | Purchase preview updates Gold, quota, rest state, and next action. | Immediate. | Opportunity cost is visible. |
| Finish run | Final Result summarizes contract, main axis, key choices, biggest pressure, and next-run watch tag. | At run end. | The player leaves with one clear lesson. |

- [ ] Final Result can return to Main Menu or start a new run.
- [ ] No player-facing screen exposes debug-only panels, sliders, telemetry dumps, or implementation-state messages.

### Design Done

- [ ] In a 1-second Battle Screen glance, a tester can point to current `Deploy Lane` and the next spawn port.
- [ ] After switching lanes, a tester can see Bridge line, lane highlight, and spawn port highlight update immediately.
- [ ] A tester does not think units spawn from Guardian.
- [ ] A tester reads Guardian as a base entity that attacks invaders, not as a bottom HUD card or controllable hero.
- [ ] During a breach, a tester can distinguish lane gate danger, base buffer invasion, and Guardian pressure.
- [ ] Battle Result explains win/loss using at least one machine / lane / Guardian pressure cause, not debug logs.
- [ ] Reward / Shop cards communicate `warehouse -> component -> operation -> player read`, not generic buff language.
- [ ] Final Result tells the player what the run's main machine axis was and what to watch next run.
- [ ] The build preserves the soul: Queue Bridge to selected spawn port causality, plus Guardian as in-world base entity.

### Not Done Until

- [ ] Someone other than the implementer plays from Main Menu to at least one Battle Result.
- [ ] That tester can answer: "Where will the next unit spawn?" without reading a tutorial paragraph.
- [ ] That tester can answer: "Is Guardian a spawn source, a controllable hero, or a base entity?" Correct answer: base entity.
- [ ] That tester can identify one reason they won or lost using machine / lane / Guardian pressure language.
- [ ] Screenshots of Battle Screen at desktop resolution show no text overlap and no debug UI.

## 7. Known Risks

| Risk | Impact | The Tempting Shortcut | Why It Kills the Experience |
|---|---|---|---|
| Bridge causality is too weak | Critical | Show only text `Current Lane: Mid` | The player does not see machine output becoming a battlefield spawn. |
| Guardian becomes HUD | Critical | Put Guardian in a bottom / side card with HP and skill | Breaks the confirmed "in-world attacking base entity" model. |
| Guardian becomes spawn point | Critical | Spawn units at Guardian position for simplicity | Destroys spawn ports, base buffer, breach, invasion, and Guardian pressure reads. |
| Lane select becomes buttons | High | Add Left / Mid / Right UI buttons as the main control | Reverts the interaction away from clicking battlefield lanes. |
| Result pages become logs | High | Dump telemetry because it is already available | Player sees data but not cause. The learning checkpoint fails. |
| Battle Screen gets too dense | High | Show all machine internals, future queue simulation, and all event text at once | Player watches UI instead of reading machine-to-frontline causality. |
| Danger looks like recommendation | High | Make danger and selected-lane highlight visually similar | Player treats Deploy Lane as "click the red light" and ignores machine output. |
| Reward cards become generic buffs | Medium | Shorten cards to name + stat change | Player cannot connect reward choice to machine component and battlefield result. |

Do not take these shortcuts:

1. Do not make Guardian a bottom or side HUD panel.
2. Do not spawn units from Guardian.
3. Do not replace Bridge-to-port feedback with text only.
4. Do not use a standalone three-button lane selector as the primary lane input.
5. Do not turn result pages into debug logs or telemetry dumps.
